What EnvPilot Detects

Environment variables bridge configuration and code. EnvPilot statically inspects code and environment templates to catch 3 critical failure classes:

❌

Missing in .env / Template

Code references process.env.DATABASE_URL, but nobody documented it in .env.example or added it to deployment secrets. Catches fatal runtime crashes before production.

⚠️

Unused / Dead Declarations

Variables lingering in .env files from legacy refactors. Clean up obsolete configuration and prevent credentials from remaining in templates.

🔁

Duplicate Key Overwrites

Detects duplicate variable keys defined across multi-line .env files that silently overwrite each other depending on parser order.

The Code Contract

How this demo repository pairs real executable JavaScript code in src/server.js with .env.example:

📄 src/server.js (Node.js ES Module) Static AST Scanned 
import http from "node:http";

// EnvPilot AST parser extracts identifiers:
const PORT = Number.parseInt(process.env.PORT || "3000", 10);
const APP_NAME = process.env.APP_NAME || "EnvPilot Demo Service";
const NODE_ENV = process.env.NODE_ENV || "development";

const server = http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "application/json" });
  res.end(JSON.stringify({
    app: APP_NAME,
    environment: NODE_ENV,
    port: PORT,
    status: "verified"
  }));
});

export default server;

Security & Zero Secret Exposure

Designed from the ground up for safe use in untrusted CI pipelines and shared workspaces:

🔒

Keys Only, Never Values

EnvPilot parses only variable names / identifiers. Actual runtime values (passwords, JWT secrets, database connection strings) are never evaluated, read, logged, or exported.

🌐

100% Offline & Local

No telemetry, no external HTTP requests, and no phone-home servers. All AST parsing and file comparison occurs purely on the local filesystem.

📖

Strictly Read-Only

EnvPilot will never alter or overwrite your project's .env or source files. It is an auditor, not an invasive modifier.

Automated GitHub Actions CI

Every push to main runs the strict auditor. If any code references an undocumented variable, CI fails immediately before code can be merged or deployed.

⚙️ .github/workflows/envpilot-check.yml View Workflows → 
name: EnvPilot CI Audit

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "npm"
      - run: npm ci
      - name: Run EnvPilot strict audit
        run: npm run env:check
      - name: Generate JSON report
        run: npm run env:report
